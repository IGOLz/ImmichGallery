Upload implementation notes (2026-11-04)

Behavior
- File > Import… (Shift-Command-I) selects multiple files and/or folders with NSOpenPanel.
- Folders recurse, excluding hidden items, packages, and symlinks. Repeated paths within an import are deduplicated.
- Finder file URLs can be dropped on the window or a sidebar album. Album drops add both newly uploaded and existing duplicate assets to that album.
- Session-owned queue runs two uploads concurrently while browsing. Toolbar progress opens a popover with filenames, byte progress, states, duplicate/error summary, Cancel All, Retry Failed, and Clear.
- Hashing and multipart preparation run off the main actor in 1 MiB chunks. URLSession uploads from a temporary on-disk multipart body and reports actual task bytes, including multipart overhead. Temporary bodies have mode 0600 and are removed after success, failure, or cancellation. This requires temporary disk space equal to each active upload.
- Original filesystem creation/modification dates are sent; original bytes and embedded metadata are preserved. The server metadata job extracts EXIF capture date and video duration.
- Live Photo components are uploaded independently, following the web client. Server metadata jobs link matching embedded ContentIdentifier/MediaGroupUUID values and hide the motion asset. Matching filenames alone do not prove a Live Photo pair. Pairing and metadata processing are asynchronous; use Refresh after server processing if needed.
- Sandbox access is retained for selected/dropped roots until Clear or queue destruction. Existing user-selected read-write entitlement suffices; no entitlement changes. Retry retains the successful upload response when only album membership failed. Signing out cancels work.
- Queue is in memory; quitting ends it. Watched folders and persistent bookmarks were deliberately omitted as optional stretch work.
